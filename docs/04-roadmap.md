## 2. M1 · 可用的单人写作工作台

状态：**完成（2026-10-22）**。验收证据见 [需求分析第 7 节](./00-requirements.md#7-m1-验收清单) 与 [上下文交接](./05-context-handoff.md#2-已验证基线2026-10-22)。

目标：一个作者可以真实写完并预览一章。

范围（已锁定）：

- 书架：统计、继续写作、筛选搜索、新建作品。
- 作品：资料编辑、分卷、章节增删改、字数、导出。
- 编辑器：纯文本、自动保存、本地恢复、字数、专注模式、大纲、状态、目标、AI 侧栏。
- 预览：安卓机身、五平台皮肤、真实分页、翻页、阅读设置、目录、跨章。
- 设置：主题、笔名、每日目标、AI 状态。
- 后端：SQLite schema、种子数据、作品/卷/章/保存/版本/导出/AI 接口。
- 文档：需求、设计、架构、数据、路线图、交接。

明确不做（M1 当时）：富文本、多人实时、账号登录、云同步、批注、拖拽排序、故事圣经、全文搜索。其中故事圣经与书封已在随后以增量交付，见 2.1。

验收：见 [需求分析第 7 节](./00-requirements.md#7-m1-验收清单)。

## 2.1 增量交付 · 书封与故事设定（2026-10-23 完成）

目标：让作品有可辨认的封面，并让角色、组织、地点、物品与概念在写作现场随手可查。

范围：

- 书封：新建/编辑作品上传 JPG/PNG/WebP，客户端 4:5 居中裁剪为 800×1000，服务端校验 data URL 与文件头；书架、作品页统一渲染；可更换、移除。
- 故事设定：五类实体 CRUD；名称、一句话标签、摘要、详细设定、识别色；搜索、类型筛选、详情。
- 编辑器接入：宽屏右侧标签页「故事设定」，窄屏右侧抽屉；与 AI 面板共用停靠区，切换不丢失草稿。
- 数据：`works.cover_image`、`story_entities`，迁移至 `user_version = 2`。
- 边界：设定不进入正文、预览、TXT / Markdown 与网页；整书 JSON 备份会包含设定。封面仅存本地 SQLite，不接对象存储。

验收：

- 真实 Chrome 1440 / 390 宽度走通上传、刷新持久化、书架渲染、设定新建/编辑/筛选/详情/删除。
- 无效封面（错误格式、超大文件）被服务端拒绝；清空封面恢复底色版式。
- 390 宽抽屉 `scrollWidth = innerWidth = 390`；新建设定弹窗完整覆盖视口，不被抽屉裁切。
- `npm run typecheck`、`npm run build` 通过。

证据见 [上下文交接第 2 节](./05-context-handoff.md#2-已验证基线2026-10-23)。

## 2.2 增量交付 · 章节插画（2026-10-23 完成）

目标：作者可以在章节里插入自定义插画，并在写作现场管理与预览，同时保持正文纯文本和自动保存协议不变。

范围：

- 插入：JPG / PNG / WebP，源文件 ≤20 MB；客户端等比缩到最长边 1400，WebP 质量递减压缩，编码不可用时退回 JPEG 白底；单图解码后 ≤1.15 MB。
- 锚点：按段落定位，`0` 为正文之前，`N` 为第 N 段之后；插入时默认取当前光标所在段落。正文后续改写时在读取端钳制锚点，不清空插画。
- 编辑：可改锚点与图注（≤120 字），可删除；更换图片需删除后重新插入。
- 编辑器：正文下方「插画」管理区；文章顶栏提供带数量的快捷入口；桌面与手机均可上传、编辑、删除。
- 预览：阅读器在锚点段落后渲染图片与图注，限制高度不超过正文可视高度的 60%，并参与真实分页重排。
- 数据：`chapter_illustrations` 独立表；图片存 BLOB，列表只取元数据；`/api/illustrations/[id]/image` 单独返回二进制并允许长期私有缓存；迁移至 `user_version = 3`。
- 边界：插画不写入正文、不改变字数/段落数、不创建版本快照、不更新章节或作品编辑时间。TXT / Markdown 仍只含文字；后续网页与整书 JSON 导出会包含插画。

验收：

- 真实 Chrome 1440 / 390 走通上传、默认锚点、改锚点与图注、删除、图片接口与缓存头。
- 无效图片与非法锚点被 400 拒绝；预览中插画出现在正确段落后，翻页后仍可见且页数稳定。
- 390 宽编辑器、预览与弹窗无横向溢出；弹窗完整覆盖视口。
- 验收后清理临时数据，演示库恢复 2 本作品、7 个未删除章节、0 张插画；当时 `PRAGMA user_version = 3`（后续多账号增量已升至 4）。
- `npm run typecheck` 与 `npm run build` 均通过。

证据见 [上下文交接第 2 节](./05-context-handoff.md#2-已验证基线2026-10-23)。

## 2.3 增量交付 · 本机多账号与整书迁移（2026-10-23 完成）

目标：让同一台机器上的多名作者、编辑与读者拥有清晰边界，并让一本书可以连书封、设定与插画一起备份、迁移。

范围：

- 账号：本机注册/登录/登出，账号 3–24 位小写字母/数字/下划线，密码 8–128 位；scrypt + 随机盐哈希，会话 30 天，数据库只存令牌哈希。
- 演示数据接管：首个注册账号继承 M1 演示作品、成员关系与统计；后续账号从空书架开始。
- 成员：owner / editor / commenter / reader 四级；所有者按账号邀请、改角色、移除；作者 owner 不可改不可移除。
- 权限：所有作品读函数按 `work_members` 过滤，写函数统一 `requireWorkRole` / `requireChapterEditor`；无成员关系 404，角色不足 403。
- 界面：作品页成员卡片、角色门控、只读成员进入预览、书架角色徽标、登录/注册页、中文 404。
- 导出：整书 JSON（`inkdock/1`）包含作品资料、书封、设定、卷章正文与插画；TXT / Markdown 仍只含文字。
- 导入：书架文件选择，校验版本与条目上限，在单事务中新建一本归当前账号所有的作品；不覆盖、不合并。
- 数据：`users.password_hash` / `password_salt`、`sessions`、`work_members` 实际启用；迁移至 `user_version = 4`。

验收：

- 两个账号：首账号接管 2 本演示作品；第二账号空书架，直接访问作品页、导出与自动保存接口均被拒绝。
- 所有者邀请第二账号为读者：读者无写作/删除/成员管理入口，章节进入预览，写作接口 403。
- 改为编辑后可新建/删除卷章，仍看不到成员管理；移除后对方立即 404。
- 整书 JSON 导出后由另一账号导入：卷章结构、书封、设定、插画、状态与目标字数完整保留。
- 登录页、成员卡片、只读作品页与 404 在 1440 / 390 无横向溢出；`npm run typecheck` 与 `npm run build` 通过。

证据见 [上下文交接第 2 节](./05-context-handoff.md#2-已验证基线2026-10-23)。

## 2.4 增量交付 · 网页导出、账号安全与读者注册（2026-10-23 完成）

目标：让作品可以直接变成可分发的阅读网页，让普通读者能自行注册并获得邀请，同时让本机账号可以安全改密。

范围：

- 网页导出：新增 `format=html`，把目录、正文、书封与插画输出为单个自包含 HTML；无脚本、无外部资源，内联打印与深浅色样式。
- 安全：所有用户文本显式转义，图片只允许 JPEG / PNG / WebP data URI；响应带严格 CSP 与附件下载头；任意成员（含读者）可导出。
- 改密：设置页新增账号安全卡片与 `POST /api/auth/password`；校验当前密码、拒绝同密码；成功后保留当前会话并删除其他会话。
- 读者入场：登录/注册页与空书架明确说明作者与读者都可注册、读者由所有者按账号邀请；导出面板增加网页 HTML 项。
- 数据：不改 schema；网页导出只读，不写数据库、不产生版本或统计。

验收：

- 所有者与只读读者均可下载 HTML；封面与插画内嵌且真实加载；目录、章节字数与空章提示正确。
- 注入的 `<script>` 与事件处理器只作为转义文本出现，不生成元素；导出无脚本、无渐变、无外部请求。
- 改密后当前会话保持，其他会话 401，旧密码失效、新密码可用；测试后恢复原密码。
- 导出页、作品导出卡片、设置账号安全卡片、注册页在 1440 / 390 无横向溢出；深色媒体与打印媒体规则经 CDP 模拟验证。
- `npm run typecheck` 与 `npm run build` 通过。

证据见 [上下文交接第 2 节](./05-context-handoff.md#2-已验证基线2026-10-23)。

1. 版本历史界面：列表、字数差异、预览、恢复。
2. 章节拖拽排序与跨卷移动，重排时保持稳定。

验收：连续写作 1 小时无保存焦虑；所有列表操作有撤销或确认；手机端无溢出。

## 8. 任务规范

### 8.1 任务粒度

一个任务应当：

- 在 0.5–2 小时内可完成；
- 有明确的用户可见结果；
- 有可执行的验收步骤；
- 不跨两个里程碑；
- 不依赖未决定的架构。

### 8.2 状态定义

| 状态 | 含义 |
| --- | --- |
| backlog | 已记录，未排期 |
| ready | 需求清楚，可开工 |
| in_progress | 正在做，且只有一项 |
| review | 代码完成，等待浏览器/构建验证 |
| done | 验收通过，文档同步 |
| dropped | 明确不做，记录原因 |

### 8.3 完成定义（DoD）

- 功能在真实浏览器中走通主路径与一个边界路径。
- `npm run typecheck` 通过；里程碑收尾时 `npm run build` 通过。
- 无新增硬编码颜色、渐变、emoji。
- 手机与桌面均无横向溢出。
- 文档中的接口、表结构、状态与实现一致。
- 如修改 UI，至少在 1440 宽与 390 宽截图检查。
