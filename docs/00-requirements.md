## 1. 产品定位

墨坞是一款**本地优先的小说创作与协作工作台**：把「写、管、看」放在同一个安静的空间里。

一句话：**为长篇写作准备的书桌，而不是又一个内容编辑器。**

它解决三类问题：

1. 长篇结构混乱：作品、卷、章、设定、版本没有统一归宿。
2. 写作过程被打断：保存焦虑、平台排版差异、发布前反复复制粘贴。
3. 协作缺少边界：多人改稿时不知道改了什么、谁在改、以哪一版为准。

### 1.1 产品原则

| 原则 | 含义 | 直接约束 |
| --- | --- | --- |
| 写作优先 | 打开即写，路径最短 | 书架提供「继续写作」；编辑器加载不超过一次跳转 |
| 本地优先 | 数据先落本机，离线可恢复 | SQLite + 本地草稿双保险；不依赖云服务才能写作 |
| 结构清晰 | 书、卷、章是硬结构 | 章节必须归属某一卷；排序稳定可预期 |
| 预览即真相 | 发布效果在写作现场可见 | 手机预览、五个平台排版模拟、真实分页翻页 |
| 克制表达 | 界面是纸，不是主角 | 无渐变、无 emoji、单一强调色、胶囊几何 |

### 1.2 非目标

- M1 不追求富文本或 Markdown 渲染。正文以纯文本为唯一事实源，降低格式污染与协作冲突。
- M1 不做真实账号体系、云端同步、实时协作。数据模型与接口预留演进空间。
- 不做社区、书评、打赏、推荐算法。
- 不复制任何平台官方客户端，仅做排版与交互的近似模拟，并在界面中标注「模拟预览」。

## 2. 用户与场景

### 2.1 用户画像

**主用户：长篇网文作者（个人）**
- 同时维护 1 至 3 本书，每本 3 至 6 卷，单章 2000 至 6000 字。
- 关心：自动保存、字数、卷章结构、手机端观感、不同平台导入后的排版差异。
- 设备：桌面写作 + 手机随时查看。

**次用户：协作作者 / 责任编辑**
- 与主作者共写或改稿，需要批注、版本和权限边界。
- M1 只落数据模型与角色定义，M2 开放邀请与批注，M3 实时协作。

### 2.2 核心场景

1. **续写**：打开书架，点击「继续写作」，在 3 秒内回到上次光标附近，开始输入。
2. **整理结构**：新增第二卷，把草稿章节归入新卷，调整卷内顺序，检查每卷字数。
3. **发布前检查**：切到手机预览，依次看起点、番茄、晋江、微信读书、七猫的排版，翻页确认断行与章节节奏。
4. **灵感协作**：把一段正文交给 AI 做润色或续写建议，人工决定是否插入。
5. **随时查设定**：写到人物、组织、地点或规则时，在编辑器右侧翻开故事设定，快速确认名字、关系与伏笔。
6. **离线写作**：网络中断时继续写，恢复后自动补交；即使进程崩溃，本地草稿仍可恢复。

## 3. 信息架构与核心概念

```
用户 user
└── 作品 work（书）
    ├── 书封 cover
    ├── 成员 membership（M2）
    ├── 设定 story_entity（已交付）
    ├── 卷 volume
    │   └── 章 chapter
    │       ├── 版本 revision
    │       └── 批注 comment（M3）
    └── AI 会话 ai_session（M2）
```

- **作品**：版权与统计的最小单位，拥有书名、简介、类型、封面、目标字数、连载状态。
- **书封**：可为空的图片，也可退回平涂底色与书名排版；只属于作品展示，不进入正文。
- **故事设定**：角色、组织、地点、物品、概念五类，记录名称、标签、摘要、详细描述与识别色，按作品隔离。
- **卷**：作品内的结构层，必须存在。新作品自动创建「第一卷」。
- **章**：写作的最小单元，必须归属一卷；保存正文、状态、排序、字数。
- **版本**：章节正文的不可变快照，用于回溯和误删恢复。
- **平台模拟**：不是数据实体，是读取作品内容的一套渲染皮肤与分页器。

### 3.1 状态定义

| 对象 | 状态 | 含义 |
| --- | --- | --- |
| 作品 | serializing | 连载中 |
| 作品 | completed | 已完结 |
| 作品 | paused | 暂停更新 |
| 作品 | archived | 已归档（软删除，界面不可见） |
| 章节 | draft | 草稿，仅在本地工作台可见 |
| 章节 | ready | 待发布，作者已完成本轮修改 |
| 章节 | published | 已发布，留作平台同步标记 |

状态只影响展示与筛选，不影响编辑权限。

## 5. 写作可靠性要求

自动保存是产品的地基，按以下规则验收：

1. **RPO（可容忍丢失）**：进程正常关闭时 0 字丢失；进程崩溃时，最多丢失最近 0.9 秒输入，且有 localStorage 副本。
2. **保存触发**：内容变化后 900 ms 防抖；持续输入时每 20 s 强制保存；失焦、页面隐藏、关闭前补交。
3. **本地副本**：每次输入即写 localStorage，服务端确认后清理；若服务端时间戳落后于本地副本，刷新后提示恢复。
4. **冲突**：保存携带 `baseUpdatedAt`。服务端版本不一致返回 409，不静默覆盖。用户选择载入远端或明确覆盖。
5. **失败重试**：网络失败后指数退避（6s、12s、24s，封顶 30s），恢复在线后立即补交。
6. **版本快照**：正文变化且距上一快照超过 15 分钟时自动创建；手动快照接口可随时创建（版本历史界面在 M1.5）；恢复旧版本前先快照当前版本。
7. **数据完整性**：章节必须属于存在的卷；删除作品为软删除；卷删除仅限空卷；所有写入校验归属关系。

## 6. 非功能需求

### 6.1 性能

- 首屏（本机 dev/prod）在 2.5 s 内可交互；书架数据查询 < 50 ms（100 本书、10000 章规模）。
- 编辑器输入无可感知卡顿；1 万字章节滚动流畅。
- 分页计算在 50 ms 内完成；调整字号后 1 帧内重排。

### 6.2 兼容与响应式

- 断点：手机 < 640，平板 640–1023，桌面 1024–1439，宽屏 ≥ 1440。
- 核心流程在 390×844 和 1440×900 下均可用；编辑器在手机端保留侧栏抽屉。
- 浏览器：Chrome / Edge 最新两个大版本；Safari 17+ 尽力支持。

### 6.3 无障碍

- 正文对比度 ≥ 4.5:1；所有可点击元素有可见焦点环。
- 图标按钮必须有 `aria-label`；对话框焦点锁定并可 Esc 关闭。
- 动效尊重 `prefers-reduced-motion`。
- 不用颜色作为唯一状态提示，状态同时有文字。

### 6.4 安全与隐私

- M1 数据仅本机；API 无外部鉴权，部署到公网前必须补账号与 CSRF 防护（M2）。
- AI 密钥仅存在服务端环境变量，不写入数据库、不返回浏览器、不写日志。
- 输出到页面的用户内容由 React 转义；导出文件名做安全处理。
- 本地数据库与草稿不包含密钥。
- 书封通过 JSON data URL 传输，服务端限制总字符数、解码字节数并校验 JPEG / PNG / WebP 文件头；不按扩展名信任上传内容。
- 故事设定写入校验作品归属、类型枚举、名称与文本长度；React 默认转义，不渲染 HTML。

### 6.5 可维护性

- TypeScript strict；数据层集中，组件不直接拼 SQL。
- 设计令牌唯一来源：`src/app/globals.css`；页面不写硬编码品牌色（平台皮肤除外）。
- 文档与实现同批更新；每个里程碑有验收清单。

## 9. 关键决策摘要

1. 纯文本正文，不做富文本。格式属于发布层，不属于创作事实层。
2. SQLite 本地单文件，先零运维；协作期升级为服务端数据库并保留导入通道。
3. 分页用 CSS 多栏真实排版，而非按字数估算，保证预览可信。
4. M1 的「协作」只落角色和数据结构，不宣称实时多人。
5. AI 是可插拔能力，未配置时界面诚实降级。
6. 书封在客户端完成裁剪与压缩，服务端只做安全校验与存储；M1 不引入对象存储。
7. 故事设定是写作参考，不与正文混合；后续双向链接通过关联表实现，不改纯文本事实层。
