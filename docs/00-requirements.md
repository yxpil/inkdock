## 1. 产品定位

墨坞是一款**本地优先的小说创作与协作工作台**：把「写、管、看」放在同一个安静的空间里。

一句话：**为长篇写作准备的书桌，而不是又一个内容编辑器。**

它解决三类问题：

1. 长篇结构混乱：作品、卷、章、设定、版本没有统一归宿。
2. 写作过程被打断：保存焦虑、平台排版差异、发布前反复复制粘贴。
3. 协作缺少边界：多人改稿时不知道改了什么、谁在改、以哪一版为准。

### 1.1 产品原则

| 原则 | 含义 | 直接约束 |
| --- | --- | --- |
| 写作优先 | 打开即写，路径最短 | 书架提供「继续写作」；编辑器加载不超过一次跳转 |
| 本地优先 | 数据先落本机，离线可恢复 | SQLite + 本地草稿双保险；不依赖云服务才能写作 |
| 结构清晰 | 书、卷、章是硬结构 | 章节必须归属某一卷；排序稳定可预期 |
| 预览即真相 | 发布效果在写作现场可见 | 手机预览、五个平台排版模拟、真实分页翻页 |
| 克制表达 | 界面是纸，不是主角 | 无渐变、无 emoji、单一强调色、胶囊几何 |

### 1.2 非目标

- M1 不追求富文本或 Markdown 渲染。正文以纯文本为唯一事实源，降低格式污染与协作冲突。
- 本机多账号与作品成员角色已提前交付，但仍是单机单进程：不做邮箱注册、找回密码、第三方登录、跨设备同步或实时协作。数据模型与接口为后续云端演进保留空间。
- 不做社区、书评、打赏、推荐算法。
- 不复制任何平台官方客户端，仅做排版与交互的近似模拟，并在界面中标注「模拟预览」。

## 2. 用户与场景

### 2.1 用户画像

**主用户：长篇网文作者（个人）**
- 同时维护 1 至 3 本书，每本 3 至 6 卷，单章 2000 至 6000 字。
- 关心：自动保存、字数、卷章结构、手机端观感、不同平台导入后的排版差异。
- 设备：桌面写作 + 手机随时查看。

**次用户：协作作者 / 责任编辑**
- 与主作者共写或改稿，需要批注、版本和权限边界。
- 本机账号、作品成员与角色边界已交付；批注与实时协作仍在 M2 / M3。评论角色暂为只读，功能未落地前界面明确标注「评论功能待后续」。

**第三用户：普通读者**
- 自己注册本机账号，由作品所有者按账号邀请，只阅读、预览和导出，不参与写作。
- 读者可以带着自己的书架使用工作台；未被邀请时书架为空，而不是被拒绝注册。

### 2.2 核心场景

1. **续写**：打开书架，点击「继续写作」，在 3 秒内回到上次光标附近，开始输入。
2. **整理结构**：新增第二卷，把草稿章节归入新卷，调整卷内顺序，检查每卷字数。
3. **发布前检查**：切到手机预览，依次看起点、番茄、晋江、微信读书、七猫的排版，翻页确认断行与章节节奏。
4. **灵感协作**：把一段正文交给 AI 做润色或续写建议，人工决定是否插入。
5. **随时查设定**：写到人物、组织、地点或规则时，在编辑器右侧翻开故事设定，快速确认名字、关系与伏笔。
6. **离线写作**：网络中断时继续写，恢复后自动补交；即使进程崩溃，本地草稿仍可恢复。
7. **给章节配图**：写完一段后在光标处插入自制插画，补一句图注，切到手机预览确认它出现在正确段落之后，再继续写下一段。
8. **本机分工**：作者注册账号后，把编辑按账号加入作品；对方登录后只看到被邀请的书，可写作但不能管理成员。读者只能打开预览与导出，看不到编辑器。
9. **换机迁移**：作者把整书导出为 JSON，在另一台机器注册账号后导入，书封、设定、卷章与插画完整恢复为一本新作品。
10. **直接分享成网页**：作者把作品导出为单个 HTML 文件，封面与插画已内嵌；读者双击即可离线阅读，不需要安装应用或登录。
11. **读者入场**：读者自行注册账号，把账号告诉作者；作者按账号邀请后，共享作品出现在读者书架，读者可预览并导出，但看不到写作入口。
12. **核对之后改密**：作者在设置里输入当前密码与新密码；改密成功后当前浏览器保持登录，其他会话被要求重新登录。

## 3. 信息架构与核心概念

```
用户 user（本机账号）
└── 作品 work（书）
    ├── 书封 cover（已交付）
    ├── 成员 membership（已交付：owner / editor / commenter / reader）
    ├── 设定 story_entity（已交付）
    ├── 卷 volume
    │   └── 章 chapter
    │       ├── 版本 revision
    │       ├── 插画 illustration（已交付）
    │       └── 批注 comment（M2）
    └── AI 会话 ai_session（M2）
```

- **用户**：本机注册账号，拥有笔名、账号标识与头像色；密码只存加盐哈希。
- **成员**：用户与作品的关系与角色。一个作品至少有一个所有者，成员关系是访问边界，不是展示标签。
- **作品**：版权与统计的最小单位，拥有书名、简介、类型、封面、目标字数、连载状态。
- **书封**：可为空的图片，也可退回平涂底色与书名排版；只属于作品展示，不进入正文。
- **故事设定**：角色、组织、地点、物品、概念五类，记录名称、标签、摘要、详细描述与识别色，按作品隔离。
- **章节插画**：属于某一章节的展示图片，按段落序号锚定并带可选图注；不进入正文、字数与版本。TXT / Markdown 导出不含插画，网页与整书 JSON 导出会包含。
- **卷**：作品内的结构层，必须存在。新作品自动创建「第一卷」。
- **章**：写作的最小单元，必须归属一卷；保存正文、状态、排序、字数。
- **版本**：章节正文的不可变快照，用于回溯和误删恢复。
- **平台模拟**：不是数据实体，是读取作品内容的一套渲染皮肤与分页器。

### 3.1 状态定义

| 对象 | 状态 | 含义 |
| --- | --- | --- |
| 作品 | serializing | 连载中 |
| 作品 | completed | 已完结 |
| 作品 | paused | 暂停更新 |
| 作品 | archived | 已归档（软删除，界面不可见） |
| 章节 | draft | 草稿，仅在本地工作台可见 |
| 章节 | ready | 待发布，作者已完成本轮修改 |
| 章节 | published | 已发布，留作平台同步标记 |

作品与章节状态只影响展示与筛选，不影响成员权限；读写权限由作品角色决定。

| ILL-08 | 图片替换、跨章画廊、拖拽排序与图注排版预设 | P2 | backlog（M4） |

插画与正文分离是硬约束：正文仍是唯一文本事实源，插画只描述「在第几段之后显示什么图」。正文被改写后，读取端把锚点钳制到当前段落数，不因段落变化丢图或报错。更换图片需删除后重新插入。

- 账号只存在本机 SQLite，没有邮箱验证、找回密码、删除账号或第三方登录。忘记密码只能由数据库管理员直接处理；已登录时可在设置页改密。
- 「评论」角色为批注功能预留，当前没有批注 UI，行为与阅读一致；界面必须如实说明，不能让人误以为可以评论。
- 成员关系只控制同一台机器上的访问；不是公网多租户方案。公网部署前必须补 CSRF、限流、HTTPS、secure cookie 与备份策略。
- 导入不得覆盖既有作品，不得把原作者写成导入者以外的账号；`authorName` 仅作为备份元数据保留，导入后作品所有者是当前账号。
- 网页导出是阅读副本，不是编辑备份：不包含故事设定、版本、成员与写作数据，不可重新导入。需要无损迁移时使用整书 JSON。

## 5. 写作可靠性要求

自动保存是产品的地基，按以下规则验收：

1. **RPO（可容忍丢失）**：进程正常关闭时 0 字丢失；进程崩溃时，最多丢失最近 0.9 秒输入，且有 localStorage 副本。
2. **保存触发**：内容变化后 900 ms 防抖；持续输入时每 20 s 强制保存；失焦、页面隐藏、关闭前补交。
3. **本地副本**：每次输入即写 localStorage，服务端确认后清理；若服务端时间戳落后于本地副本，刷新后提示恢复。
4. **冲突**：保存携带 `baseUpdatedAt`。服务端版本不一致返回 409，不静默覆盖。用户选择载入远端或明确覆盖。
5. **失败重试**：网络失败后指数退避（6s、12s、24s，封顶 30s），恢复在线后立即补交。
6. **版本快照**：正文变化且距上一快照超过 15 分钟时自动创建；手动快照接口可随时创建（版本历史界面在 M1.5）；恢复旧版本前先快照当前版本。
7. **数据完整性**：章节必须属于存在的卷；删除作品为软删除；卷删除仅限空卷；所有写入校验归属关系。
8. **权限边界**：所有作品读写先校验成员角色。移除成员或降级后，旧会话不能凭缓存继续写入；客户端隐藏按钮不作为安全措施。

## 6. 非功能需求

### 6.1 性能

- 首屏（本机 dev/prod）在 2.5 s 内可交互；书架数据查询 < 50 ms（100 本书、10000 章规模）。
- 编辑器输入无可感知卡顿；1 万字章节滚动流畅。
- 分页计算在 50 ms 内完成；调整字号后 1 帧内重排。
- 插画在客户端完成缩放与压缩后再上传；图片写入宽高预留比例，加载完成后只重测一次页数。

### 6.2 兼容与响应式

- 断点：手机 < 640，平板 640–1023，桌面 1024–1439，宽屏 ≥ 1440。
- 核心流程在 390×844 和 1440×900 下均可用；编辑器在手机端保留侧栏抽屉。
- 浏览器：Chrome / Edge 最新两个大版本；Safari 17+ 尽力支持。

### 6.3 无障碍

- 正文对比度 ≥ 4.5:1；所有可点击元素有可见焦点环。
- 图标按钮必须有 `aria-label`；对话框焦点锁定并可 Esc 关闭。
- 动效尊重 `prefers-reduced-motion`。
- 不用颜色作为唯一状态提示，状态同时有文字。

### 6.4 安全与隐私

- 当前仅本机使用：已有账号、会话与作品成员鉴权，但仍无 CSRF/Origin 校验、登录限流与 HTTPS 强制；部署到公网前必须补齐这些防护。
- 密码使用 scrypt + 每账号 16 字节随机盐，校验使用恒定时间比较；数据库不存明文密码。会话 cookie 为 httpOnly、sameSite=lax、30 天过期，数据库只存令牌 SHA-256 哈希。改密成功保留当前会话，其余会话立即删除。
- 无成员关系统一返回 404，角色不足返回 403，避免通过接口探测他人作品是否存在。前端隐藏操作只是体验优化，服务端始终重新校验。
- AI 密钥仅存在服务端环境变量，不写入数据库、不返回浏览器、不写日志。
- 输出到页面的用户内容由 React 转义；导出文件名做安全处理。
- 本地数据库与草稿不包含密钥。
- 书封通过 JSON data URL 传输，服务端限制总字符数、解码字节数并校验 JPEG / PNG / WebP 文件头；不按扩展名信任上传内容。
- 故事设定写入校验作品归属、类型枚举、名称与文本长度；React 默认转义，不渲染 HTML。
- 章节插画通过独立接口写入，服务端校验 data URL 前缀、文件头、解码字节数与章节归属；图片读取只对未删除章节与未归档作品开放，不按扩展名信任上传内容。
- 整书导入限制请求体与条目数量，校验所有枚举、长度、图片文件头与归属；导入在事务中执行，失败回滚，不会留下半本书。
- 网页导出对标题、正文、图注与作品资料统一做 HTML 转义；只嵌入 JPEG / PNG / WebP data 图片；响应带严格 CSP，禁止脚本、表单与外部资源。故事设定与写作数据不进入网页。

### 6.5 可维护性

- TypeScript strict；数据层集中，组件不直接拼 SQL。
- 设计令牌唯一来源：`src/app/globals.css`；页面不写硬编码品牌色（平台皮肤除外）。
- 文档与实现同批更新；每个里程碑有验收清单。

## 9. 关键决策摘要

1. 纯文本正文，不做富文本。格式属于发布层，不属于创作事实层。
2. SQLite 本地单文件，先零运维；协作期升级为服务端数据库并保留导入通道。
3. 分页用 CSS 多栏真实排版，而非按字数估算，保证预览可信。
4. M1 的「协作」只落角色和数据结构，不宣称实时多人。
5. AI 是可插拔能力，未配置时界面诚实降级。
6. 书封在客户端完成裁剪与压缩，服务端只做安全校验与存储；M1 不引入对象存储。
7. 故事设定是写作参考，不与正文混合；后续双向链接通过关联表实现，不改纯文本事实层。
8. 章节插画按段落锚定并独立存储，正文保持纯文本；图片元数据与二进制分离，避免大图进入页面载荷。
9. 插画属于展示层，不影响字数、版本与编辑时间；TXT / Markdown 保持纯文字，带图阅读由单文件网页导出承担，EPUB / PDF 作为后续发布能力单独设计。
10. 账号先做本机多用户，不做邮箱、找回或第三方登录。它解决同一台机器上的访问边界，不冒充云协作。
11. 角色在服务端查询与写入层双重校验；无成员关系返回 404，角色不足返回 403。评论角色在批注落地前保持只读并明确说明。
12. 整书迁移使用带版本号的 JSON，导入只新建作品并在单事务内完成；TXT / Markdown 保持纯文本导出，不承担备份职责。
13. 网页导出采用自包含 HTML，不依赖服务器即可阅读；用户文本全部转义、禁止脚本与外部资源，因此分享文件不会把工作台数据或执行能力带给读者。
14. 改密要求当前密码并轮换其他会话；当前会话保留避免用户改密后被立即踢出，但不能让旧密码继续有效。
